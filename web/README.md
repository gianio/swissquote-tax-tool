# Browser‑only app — E‑Steuerauszug Generator (any bank → eCH‑0196)

The **least‑compliance‑exposure** build: the entire pipeline runs **in the
visitor's browser**, with **no server**. Your CSV/PDF never leaves your device,
so there's no data to store, log, or breach. Host it as plain static files on
any domain (GitHub Pages, Netlify, S3, …).

## What works fully client‑side today

- **Input: CSV *and* Kontoauszug PDF.** The PDF is parsed in the browser with
  **pdf.js** (`pdfparse.js`, a port of the Python coordinate parser): identity,
  per‑currency **cash balances**, and all transactions.
- **eCH‑0196 v2.2 XML** — generated by `core.js` and **XSD‑valid** (verified in
  `tests/test_web_poc.py`). Swiss **Valorennummern**, cash accounts, minimal
  tax‑value mode.
- **Barcode PDF (macro‑PDF417).** `barcode.js` runs the *exact* Python
  `pdf417gen` encoder (the same fork the server uses) in the browser via a
  **vendored Pyodide** — no CDN, no network. Python returns the black‑module
  coordinates per segment and **pdf‑lib** draws them into a PDF. The output is
  **byte‑identical** to the server encoder for the same statement (verified by
  comparing module coordinates), so the barcode scans in softax just like the
  server's. First click loads the Python runtime once (~4 s), locally.
- **Carry‑forward.** `carryforward.js` reads last year's positions from either a
  previous **eCH‑0196 XML** (exact) or a softax **Wertschriften­verzeichnis PDF**
  (via pdf.js), so this year's trades bind onto titles already listed in the tax
  software instead of being created twice. ISIN check‑digit (Luhn) validation
  filters IBAN false‑positives; matched openings show as “Bestand 01.01.
  (Vorjahr)”.
- **Dashboard** — Zugänge/Abgänge/Dividenden, Kontostände, category chart,
  dividends & positions tables.
- **Download** the XML and the barcode PDF. No network calls at all — pdf.js,
  pdf‑lib, Pyodide and `pdf417gen` are all vendored in `vendor/`.

## Any bank, any canton

- **Swissquote** PDF/CSV is recognised automatically.
- **Any other bank's CSV/TXT export** goes through `importers.js`: preamble
  lines are skipped, the delimiter/decimal separator/date format are detected,
  columns are auto‑matched by DE/EN/FR header synonyms and transaction types by
  keyword — both can be re‑assigned in the UI with a live preview. A mapping
  can be saved per bank as a local *Bankprofil* (localStorage, column names only).
- **Manual entry** for banks without an export: *Bestand 31.12.*, dividends,
  trades and cash balances from the Vermögensausweis.
- **All 26 cantons**: eCH‑0196 is the national standard, so the XML/barcode PDF
  works with any cantonal tax software that imports eCH‑0196. Carry‑forward
  accepts the previous year's eCH‑0196 XML (all cantons) or a SofTax control
  printout PDF.

## Privacy, legal, payment

- **Consent popup** on first visit (local processing, no sharing; AGB +
  Datenschutz must be accepted).
- **Content‑Security‑Policy** in `index.html` lets the page talk only to its
  own origin, so data cannot be sent elsewhere even by accident.
- **Legal drafts**: `agb.html`, `datenschutz.html`, `impressum.html` — fill in
  the `[placeholders]` and have them reviewed before going public.
- **Paywall (off)**: `paywall.js` + `paid.html`, configured in `config.js`
  (`paywall.enabled: false`). TWINT and credit card via a hosted checkout in a
  separate window (statement stays in memory), verified by a small server
  endpoint. Preview the dialog with `index.html?paywall=demo`. Being fully
  client‑side, the gate can be bypassed by technical users — accepted on
  purpose for the no‑upload design.
- **Preview**: step 4 renders part of the statement; while locked, rows after
  the first three are masked (not just blurred) until payment.

## Try it

Open `web/index.html`, or serve statically (still 100 % client‑side):

```bash
cd web && python3 -m http.server 8080   # http://localhost:8080
```

## Scanned PDFs / OCR

Normal Swissquote PDFs have a **text layer** and are parsed exactly — this is
more reliable than OCR. A **scanned/photographed** statement has no text layer;
the app detects that and asks for the digital original, because OCR cannot
recover the column structure of the statement reliably enough for a tax export.

## Parity with the server version

The browser build now covers the full pipeline — input (CSV + PDF), eCH‑0196
XML, dashboard, **carry‑forward**, and the **macro‑PDF417 barcode PDF**. The
only thing it deliberately doesn't do is bank‑signing: the statement is
self‑produced and marked *nicht bank‑signiert*; the tax software fills in the
official Steuerwerte on import.
